# План реализации и состояние работ

Требования: [архитектура](architecture.md). Процесс: [организация работы](team_distribution.md).

## Текущее состояние

В репозитории есть прототип коллеги: SQLite/SQLAlchemy, миграции Alembic, CRUD,
импорт HTML/изображений/WAV/MP3, оригиналы, worker, Docker и тесты.
Он ещё не адаптирован под PostgreSQL/Psycopg и упрощённые контракты MVP.
Полный набор тестов в ходе ревью не запускался: в доступном Python не было pytest.
Поэтому существующий код не отмечен как прошедший приёмку целевых задач.
P01 завершён (`done`), принят и интегрирован в `mvp`;
остальные задачи пока `todo`.
Владельцы и календарные сроки не назначаются.

Файловое хранилище, extractors, проверку входа, изоляцию процессов и тестовые
сценарии переиспользовать, где они подходят. Не удалять их только из-за другого
стека хранения. SQLite/ORM/Alembic, версии содержимого и старый внешний адаптер
знаний разрешено заменить без обратной совместимости и переноса тестовых данных.

## Границы MVP

Текст, пересылки, TXT/Markdown, пачки файлов, голосовые Telegram OGG/Opus,
WAV/MP3, веб, Telegram, поиск, обычные ответы по базе, summary/теги, правка,
подборки и автоматический граф. Один worker, один последовательный `process`
job для индекса и обогащения. Защита актуальности jobs остаётся.

Цитаты и список источников ответа, привязки к фрагментам, сегменты и таймкоды
аудио не входят в MVP. Внутренние текстовые chunks нужны только для поиска.
PDF/OCR/HTML — дополнительные адаптеры T18–T20, не блокирующие готовность MVP.

## Статусы

`todo` → `in_progress` → `review` → `done`; `blocked` — с причиной и следующим действием.
Задача начинается после завершения зависимостей. `review` — результат подготовлен
и проверен. `done` — приёмка выполнена и результат интегрирован в проект. Агент сам не коммитит и не сливает без соответствующей команды.
Отчёт содержит фактические команды/результаты и непроверенные части.

## Эксперименты E0

Код и фиксированные зависимости — в `experiments/`, инструкции и фактические
результаты — в `docs/experiments/`. Веса, секреты и личные материалы не коммитятся.
Нужны точные команды, runtime/версия/артефакт модели, параметры и несколько
примеров ответов. Достаточно времени запросов и доступного измерения памяти;
большой бенчмарк не требуется. Для P02/P04 — отдельная тестовая PostgreSQL/pgvector,
без зависимости от существующего backend. Реальный запуск не заменяется mock.

### P01. Локальная LLM по HTTP

На Mac M4 Pro 48 GB выбрать подходящие runtime и модель, проверив официальную
документацию и установленные средства. Запустить нативный OpenAI-compatible
endpoint на loopback. Не считать старые названия моделей в планах проверенными.

Приёмка:

- curl и Python получают содержательный ответ по-русски через `/v1/chat/completions`.
- Native tool calling проходит полный цикл на безопасной локальной функции:
  запрос модели → проверка аргументов → исполнение → результат модели → ответ.
- Отдельный запрос в JSON mode возвращает summary и tags; Pydantic проверяет
  поля и типы. JSON по одной лишь инструкции не подменяет JSON mode.
- После остановки и повторного запуска проверки воспроизводятся по инструкции.
- Зафиксированы версия runtime, модель/квантизация, параметры, время и доступные
  данные о памяти. Если режим не работает — явный результат и следующий шаг.

Streaming и строгая JSON Schema не обязательны и не требуют отдельного исследования.
Backend, ASR, embeddings, БД и клиенты в этой задаче не меняются.

### P02. Embeddings и поиск

Взять 20–30 заметок RU/EN, вычислить embeddings и сохранить в pgvector.
Приёмка: фиксированные точные и перефразированные запросы возвращают ожидаемые
заметки; сохранены выдача, настройки размерности/нормализации/query instruction
и время выполнения. Явный SQL через Psycopg, без ORM и без locators цитат.

### P03. Распознавание голоса

Проверить нативный ASR на Mac на записи 2–5 минут с контрольным текстом.
Обязателен OGG/Opus, характерный для Telegram; дополнительно проверить WAV/MP3.
Приёмка: из Python получается полный текст и язык, проверяются читаемость,
ошибки и время. Оригинал сохраняется локально; в отчёт попадают только
обезличенные данные. Сегменты и таймкоды из ASR не сохранять.

### P04. Минимальный RAG

Соединить P01/P02 скриптом: вопрос → retrieval → тексты контекста → обычный ответ.
Приёмка: 5–10 вопросов, включая перефразирование и отсутствие ответа в корпусе,
проверены на реальных моделях; сохранены ответы и замеченные ошибки.
Цитаты, список источников и разметка ответа не реализуются.

## Реализация

### T01. Каркас, Compose и CI

Адаптировать существующие Dockerfile, зависимости и Compose; подготовить
PostgreSQL/pgvector, команды Makefile, фиксированные зависимости и CI.
Приёмка: чистое окружение запускает БД и минимальный API; проверка кода проходит.
Модели и Telegram token не обязательны для базового API. Не переписывать все
обработчики в этой задаче; временные ограничения существующего кода обозначить.

### T02. SQL-схема и контракты

Добавить Psycopg и пул, нумерованные SQL-миграции и учёт их применения.
Зафиксировать DTO архитектуры: общие ingestion/processing состояния,
`extract/process/cleanup`, заметки, файлы, подборки, chunks, диалоги и связи.
Приёмка: схема применяется к пустой PostgreSQL, ограничения проверены;
нет ORM-моделей целевой схемы, content_version, expected_version и locators.

### T03. CRUD

Перенести операции в общий прикладной слой и SQL repositories, подключить API.
Приёмка: создать/читать/изменить/удалить текст, пагинация и валидация работают;
заголовок необязателен и выводится из первой строки. Прототип API версий заменён.
CRUD без моделей работает; интеграция производных данных завершается в T14.

### T04. Веб

Список, карточка, CRUD, прогресс и ошибки с настоящим API.
Приёмка: текст создаётся без ручного заголовка, редактируется, удаляется;
отсутствующая модель не блокирует интерфейс заметок.

### T05. Telegram

aiogram вызывает общий прикладной слой, сохраняет происхождение пересылки.
Приёмка: текст/пересылка видны в вебе, повтор доставки не создаёт дубликат,
повторная самостоятельная отправка сохраняется. Голос добавляется в T15.

### T06. Worker

Перенести jobs в PostgreSQL: занятие, lease/token, heartbeat, явный retry,
таймаут и восстановление истёкшей lease. Один worker, последовательная обработка.
Приёмка: job не занимается повторно при действующей lease, прежний token
не завершает заново занятый job, ошибка обработчика видна и не останавливает цикл.
Не добавлять несколько очередей, автоматический backoff и масштабирование.

### T07. Клиенты моделей

Раздельные клиенты генерации, embeddings и ASR с настройками и таймаутами.
Основной генератор поддерживает проверенные P01 native tools и JSON mode.
ASR возвращает `text`/`language`. Приёмка: реальные профили воспроизводимы,
неверные ответы дают определённые ошибки; тестовые адаптеры доступны для CI.

### T08. Индекс

Реализовать `process`: текст → внутренние chunks → embeddings → замена индекса.
Публикация в PostgreSQL проверяет активный job/token под блокировкой заметки.
Приёмка: повтор не дублирует chunks; отменённый job не записывает старый индекс;
текст находится векторным запросом. Отдельный index job не создаётся.

### T09. Поиск

Полнотекстовый RU/EN + dense retrieval, RRF, фильтры и `/search`.
Приёмка: точные и смысловые запросы находят заметки; ответ — ID, заголовки,
превью, score. Удалённые материалы исключены. Цитирование не реализуется.

### T10. Ответы и чат

История и бюджет контекста, инструменты поиска/чтения, обычный RAG-ответ,
веб-чат и ответы Telegram. Приёмка: модель отвечает по найденным материалам,
follow-up учитывает диалог, отсутствие данных явно отражается.
В API/интерфейсе нет citations, привязок утверждений и таймкодов.

### T11. Оригиналы и текстовые файлы

Адаптировать существующий Storage, скачивание и ошибки; добавить TXT/Markdown.
Приёмка: файл можно скачать, текст извлекается, название выводится из имени;
лимиты/пустой файл дают ошибку, неудачная запись в БД не оставляет новый оригинал.

### T12. Пачки и подборки

Import batch/items с отдельным исходом каждого файла; простые подборки и
операции из API архитектуры. Приёмка: один файл — одна заметка, сбой не отменяет
остальные; подборку можно создать автоматически для пачки и ограничить ею поиск.
Без заданной подборки пачка автоматически получает новую с заголовком по дате.
Ручная сортировка материалов не обязательна.

### T13. Обогащение

Добавить к тому же `process` после индекса генерацию summary/тегов/категории/
сущностей в JSON mode с валидацией и отображением в карточке.
Приёмка: индекс и метаданные создаются последовательным обработчиком;
ошибка генерации помечает процесс failed, сохранённые текст и индекс остаются.
Ручной retry повторяет процесс целиком. Отдельный enrich job не создаётся.

### T14. Правка и удаление

Под общей блокировкой отменять активные jobs, удалять старые производные данные,
сохранять новый текст и ставить один process. Cleanup удаляет оригинал и данные.
Приёмка: старое задание не публикует результат после правки/удаления;
ID, оригинал и подборки сохраняются при правке. Истории редакций нет.

### T15. Голос и аудио

Расширить проверку форматов до OGG/Opus, WAV, MP3; подключить ASR и голос Telegram.
Сохранить оригинал, декодировать напрямую или во временный PCM/WAV.
Приёмка: реальное голосовое проходит Telegram → полный текст → поиск;
длительность/размер/ошибки отображаются, сегменты и таймкоды не сохраняются.

### T16. Действия через диалог

Native tool calling для сохранения/правки/подборок, валидация аргументов,
ограничение числа вызовов; голос после распознавания проходит ту же логику.
Приёмка: действие действительно записано до сообщения об успехе;
неоднозначный объект вызывает уточнение; текст базы не становится инструкцией.

### T17. Граф

Автоматические связи по embeddings, пересчёт после process, Cytoscape.js.
Приёмка: граф появляется без действий по разметке, переходы к заметкам работают,
удалённые узлы и устаревшие связи не показываются. Редактор рёбер не нужен.

### T18. Дополнительно: PDF

Адаптер PDF → обычный текст с сохранением оригинала.
Приёмка: текстовый PDF читается, повреждённый даёт понятную ошибку.
Номера страниц и координаты для цитирования не требуются.

### T19. Дополнительно: OCR

Адаптировать существующий Tesseract rus+eng для изображений и PDF-сканов.
Приёмка: русский/английский текст извлекается, пустой результат/лимиты видны.
Не сохранять координаты распознанных блоков для цитирования.

### T20. Дополнительно: HTML

Адаптировать существующую загрузку по проверенному IP и Trafilatura,
сохранение HTML, ограничения адресов, редиректов, размеров и времени.
Приёмка: статья становится текстом заметки, локальные адреса отклоняются.
Не заменять подходящий сетевой код только ради другого HTTP-клиента.

### T21. Сквозная проверка

Проверить основной MVP с тестовыми моделями: оба клиента, текст/файлы/голос,
пачки, поиск/чат, правка/удаление, граф, ошибка обработки и ручной retry.
Повторно использовать подходящие тесты коллеги. Приёмка не требует сложного
моделирования отказов БД и дополнительных PDF/OCR/HTML-адаптеров.

### T22. Реальные модели

На компактном корпусе E0 проверить релевантность поиска, обычные ответы,
native tools/JSON mode, голосовой транскрипт и приемлемое время.
Приёмка: сохранены конфигурации, реальные примеры, ошибки и ограничения.
Большой бенчмарк, обязательные WER/p95/TTFT и облачный GPU не требуются.

### T23. Запуск и резервирование

Проверить Compose, настройки локального/серверного запуска, healthchecks,
логи без секретов, простой backup PostgreSQL и оригиналов.
Приёмка: запуск с нуля и один restore в отдельную БД/каталог воспроизводимы.
Во время простого backup запись/worker можно остановить; online backup не нужен.
Если сервер недоступен, проверку на нём не объявлять выполненной.

### T24. Поставка

Инструкция, демонстрация основного сценария, известные ограничения.
Приёмка: инструкция воспроизводится, E0–E5 подтверждены, статусы соответствуют
проверкам; дополнительные T18–T20 не обязательны для закрытия MVP.

## Учёт работы

### P01 — локальная LLM по HTTP

Статус: `done` (P01 и завершающий рефакторинг приняты пользователем, результат в `mvp`).
Область изменений: `experiments/p01/`, `scripts/models/`, игнорируемый
`local/ollama/`, `.gitignore`, `docs/experiments/p01.md`, запись P01.
Проверки и фактические результаты: `mvp`, исходно чистое рабочее дерево;
Ollama 0.40.16 + qwen3:8b Q4_K_M, Metal Apple M4 Pro, loopback 11435.
До и после реального перезапуска curl и Python получили русский ответ;
native tools прошли полный цикл за два запроса; API JSON mode
(`response_format=json_object`) прошёл Pydantic. Все HTTP — 200,
Python-запросы 1.019–1.541 с; память модели по `/api/ps` 5.80 GB, swap=0.
`py_compile`, `sh -n`, `pip check`, `git diff --check` — PASS;
занятый порт корректно отклоняется. Evidence и точные команды: [P01](experiments/p01.md).
Завершающий рефакторинг: существующие runtime/веса/логи перенесены в
`local/ollama/` через `mv`, inode и SHA-256 весов сохранены, без повторных загрузок.
Общие setup/serve — в `scripts/models/`; пути и loopback-адрес настраиваются.
Setup проверяет 55 файлов runtime и пропускает корректную установку.
Новые реальные curl/tools/JSON прогоны до/после перезапуска — PASS на 11435/11436,
в том числе запуск из `/private/tmp` с явными путями. Все HTTP 200,
Python 0.982–1.479 с. Evidence — `results/post-relocation/`; прежние evidence
сохранены побайтово. Исключения Git и отсутствие tracked runtime/весов/логов
проверены; занятый порт и non-loopback отклоняются. Все серверы остановлены.
