# План реализации и состояние работ

## Текущее состояние

В репозитории есть прототип коллеги: SQLite/SQLAlchemy, миграции Alembic, CRUD,
импорт HTML/изображений/WAV/MP3, оригиналы, worker, Docker и тесты.
Прототип сохраняется рабочим до замены соответствующих модулей. Целевой
backend внедряется по задачам: SQL-схема, мигратор, пул PostgreSQL/Psycopg
и DTO реализованы в T02, модельные клиенты — в T07. Прикладной CRUD T03
и PostgreSQL worker T06 реализованы и интегрированы. Веб-интерфейс T04
и индексирование T08 также приняты и интегрированы.
В T01 агент выполнил полный доступный набор из 69 тестов с `prototype` extra;
реальные OCR/ASR-модели в этом прогоне не проверялись. Прохождение тестов
прототипа не означает приёмку его переноса на целевую архитектуру.
P01–P04 приняты и интегрированы (`done`); этап E0 завершён (`done`).
T01, T02, T03, T04, T06, T07 и T08 приняты и интегрированы (`done`).
Для T04 выполнен HTTP CRUD через frontend proxy; браузерный CRUD и уход со
страницы до ответа операции ещё не подтверждены. Дополнение frontend CI
подготовлено отдельно и передано в `review`; hosted CI ещё не запускался.
Раздача dist и общий контейнерный запуск остаются отдельной интеграцией.
Этап E2 — `in_progress`, его интеграционная приёмка ещё не выполнена.
По зависимостям доступны T05, T09, T11 и T13; порядок параллельной работы
и границы ответственности приведены в разделе «Следующая итерация».
Владельцы и календарные сроки не назначаются.

Файловое хранилище, extractors, проверку входа, изоляцию процессов и тестовые
сценарии переиспользовать, где они подходят. Не удалять их только из-за другого
стека хранения. SQLite/ORM/Alembic, версии содержимого и старый внешний адаптер
знаний разрешено заменить без обратной совместимости и переноса тестовых данных.

## Границы MVP

Текст, пересылки, TXT/Markdown, пачки файлов, голосовые Telegram OGG/Opus,
WAV/MP3, веб, Telegram, поиск, обычные ответы по базе, summary/теги, правка,
подборки и автоматический граф. Один worker, один последовательный `process`
job для индекса и обогащения. Защита актуальности jobs остаётся.

Цитаты и список источников ответа, привязки к фрагментам, сегменты и таймкоды
аудио не входят в MVP. Внутренние текстовые chunks нужны только для поиска.
PDF/OCR/HTML — дополнительные адаптеры T18–T20, не блокирующие готовность MVP.

## Статусы

`todo` → `in_progress` → `review` → `done`; `blocked` — с причиной и следующим действием.
Задача начинается после завершения зависимостей. `review` — результат подготовлен
и проверен. `done` — приёмка выполнена и результат интегрирован в проект. Агент сам не коммитит и не сливает без соответствующей команды.
Отчёт содержит фактические команды/результаты и непроверенные части.
Хеши коммитов проекта в документации не ведутся; версии, digest и checksum
внешних моделей и runtime сохраняются.

## Эксперименты E0

Код и фиксированные зависимости — в `experiments/`, инструкции и фактические
результаты — в `docs/experiments/`. Веса, секреты и личные материалы не коммитятся.

### P01. Локальная LLM по HTTP

На Mac M4 Pro 48 GB выбрать подходящие runtime и модель, проверив официальную
документацию и установленные средства. Запустить нативный OpenAI-compatible
endpoint на loopback. Не считать старые названия моделей в планах проверенными.

Приёмка:

- curl и Python получают содержательный ответ по-русски через `/v1/chat/completions`.
- Native tool calling проходит полный цикл на безопасной локальной функции:
  запрос модели → проверка аргументов → исполнение → результат модели → ответ.
- Отдельный запрос в JSON mode возвращает summary и tags; Pydantic проверяет
  поля и типы. JSON по одной лишь инструкции не подменяет JSON mode.
- После остановки и повторного запуска проверки воспроизводятся по инструкции.
- Зафиксированы версия runtime, модель/квантизация, параметры, время и доступные
  данные о памяти. Если режим не работает — явный результат и следующий шаг.

Streaming и строгая JSON Schema не обязательны и не требуют отдельного исследования.
Backend, ASR, embeddings, БД и клиенты в этой задаче не меняются.

### P02. Embeddings и поиск

Взять 20–30 заметок RU/EN, вычислить embeddings и сохранить в pgvector.
Приёмка: фиксированные точные и перефразированные запросы возвращают ожидаемые
заметки; сохранены выдача, настройки размерности/нормализации/query instruction
и время выполнения. Явный SQL через Psycopg, без ORM и без locators цитат.

Статус P02: `done`. Ревью и приёмка пройдены, результат закоммичен;
обязательных исправлений кода нет.
[Отчёт P02](experiments/p02.md), код и
фиксированное окружение — `experiments/p02/`. Реально проверены 24 синтетические
заметки RU/EN, Qwen3-Embedding 0.6B Q8_0, 1024 измерения, явная L2,
query instruction; отдельный PostgreSQL 17.8 / pgvector 0.8.1 и Psycopg 3.2.13.
18 однозначных запросов: hit@1 16/18, hit@3 18/18; неоднозначный вернул обе
ожидаемые заметки. Выдача, ошибки ранжирования и время сохранены в evidence.
Выполнены реальный eval, повторный поиск без переиндексации после перезапуска БД,
проверка pin модели, SQL cosine-порядка, размерности и чтения 24 векторов;
`py_compile`, `sh -n`, `pip check`, Compose config и `git diff --check` — PASS.
Запрос без ответа возвращает ближайшие нерелевантные заметки; порог не подбирался.
Блокировок нет; P02 принята и закоммичена. Backend и корневой Compose
не менялись, пользовательская БД не использовалась.

### P03. Распознавание голоса

Проверить нативный ASR на Mac на записи 2–5 минут с контрольным текстом.
Обязателен OGG/Opus, характерный для Telegram; дополнительно проверить WAV/MP3.
Приёмка: из Python получается полный текст и язык, проверяются читаемость,
ошибки и время. Оригинал сохраняется локально; в отчёт попадают только
обезличенные данные. Сегменты и таймкоды из ASR не сохранять.

Ревью P03 пройдено: [отчёт P03](experiments/p03.md), код `experiments/p03/`.
Локальный ASR проверен на публичной русской записи LibriVox 188,171 s
с контрольным печатным текстом Чехова. Реально
проверены OGG/Opus, WAV, MP3 на whisper.cpp v1.9.5 / Metal / large-v3-turbo
Q5_0: полный `text`, `language=ru`, ASR 6,795–7,208 s с прогретым shader cache.
Расхождение литературной части с независимым печатным текстом — 0,43–0,85%;
это не достоверная WER живой речи, поскольку дословный эталон исполнения
вручную не сверялся. Найдены пропуски при
`-nt`; внутреннее выравнивание включено, печатные таймкоды удаляются в памяти,
сегменты и интервалы не сохраняются. Полные публичные транскрипты, метрики
финального и исходного прогонов сохранены. Сборка/checksum, py_compile,
sh -n и проверки декодера прошли; короткий вход без `--smoke` отвергается.
Блокировок P03 нет; личная запись и дословный TXT для её завершения не требуются.
Настоящий файл Telegram и разговорная/шумная речь здесь не проверены;
сквозная проверка реального голосового Telegram → полный текст → поиск
остаётся обязательной в T15. Статус P03 — `done`: приёмка пройдена,
результат закоммичен. Backend и бот не менялись.

Адаптировать существующие Dockerfile, зависимости и Compose; подготовить
PostgreSQL/pgvector, команды Makefile, фиксированные зависимости и CI.
Приёмка: чистое окружение запускает БД и минимальный API; проверка кода проходит.
Модели и Telegram token не обязательны для базового API. Не переписывать все

Состояние T01: `done`. Повторное ревью пройдено, результат закоммичен
и интегрирован. Эксперименты и локальные модельные данные не менялись.

Результат:

- Compose запускает PostgreSQL/pgvector `0.8.1-pg17-trixie` и API из одного
  минимального backend-образа. Отдельный project-scoped volume, healthchecks,
  API-порт на loopback; БД не публикует порт. Секреты поступают через окружение.
- Docker использует новый `app.api_app:app`: `/api/v1/health` доступен без моделей,

  и существующие тесты не изменены.
- Установка, Docker и CI используют `backend/uv.lock`. Минимальное окружение
  не устанавливает тяжёлые OCR/ASR extras. Зависимости и lockfile при этой

явным retry (метод repository и CLI --retry). Вычисление изолировано через spawn,
имеет конечный timeout; ошибка/аварийный выход/timeout не останавливают следующие
jobs. SIGINT/SIGTERM прерывают текущее вычисление, join/terminate/kill освобождают
дочерний процесс; контекст Database закрывает пул. Отсутствие обработчика или
writer даёт ошибку, без фиктивного успеха.

Публикация SQL — только через repository.publish: блокировка заметки, затем job,
проверка принадлежности/вида, processing/token, действующей lease и deleted_at.
Для extract/process требуется живая заметка; cleanup допускается только для
удалённой служебной записи. Lease проверяется после ожидания блокировок и после
callback; истечение внутри callback откатывает запись и завершение целиком.
Heartbeat, complete и fail используют ту же защиту. Промежуточные публикации
поддерживаются; последующая ошибка обработчика не удаляет уже записанные данные.
Обработчики в T06 только тестовые; настоящего извлечения, индекса, обогащения,
удаления файлов и изменения прикладных статусов заметок нет.
