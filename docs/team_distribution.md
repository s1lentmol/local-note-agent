# Распределение работы на троих

Проект: локальный LLM-агент для заметок.

Работа разделена на три направления: **хранение и импорт данных**, **LLM и поиск**, **интерфейс и визуализация**. У каждого участника собственный модуль, который можно разрабатывать параллельно с остальными.

## Участник 1 — Backend, хранение и обработка материалов

**Зона ответственности:** превратить загруженный материал в заметку с извлечённым текстом.

- Спроектировать структуру SQLite: заметки, источники, вложения, метаданные и статусы обработки.
- Реализовать API на FastAPI для создания, просмотра, редактирования и удаления заметок.
- Добавить загрузку текста, ссылок, изображений и аудиофайлов.
- Реализовать извлечение текста из веб-страниц, OCR изображений и транскрибацию аудио.
- Организовать фоновую обработку с состояниями «ожидает», «обрабатывается», «готово», «ошибка».
- Обеспечить передачу извлечённого текста в модуль участника 2 и сохранение результатов обработки.
- Подготовить Docker Compose для совместного запуска компонентов.

**Результат:** работающий сервер, который принимает материалы всех заявленных типов, хранит оригиналы и возвращает нормализованный текст.

## Участник 2 — Локальная LLM, семантический поиск и RAG

**Зона ответственности:** интеллектуальная обработка заметок и ответы по базе знаний.

- Настроить локальный запуск LLM и единый интерфейс обращения к модели.
- Реализовать генерацию краткого содержания, тегов, категории и ключевых сущностей.
- Разбивать текст на фрагменты, получать embeddings и сохранять их в Qdrant.
- Реализовать семантический поиск с привязкой результатов к исходным заметкам.
- Собрать RAG-цепочку: вопрос → поиск фрагментов → формирование контекста → ответ со ссылками на источники.
- Рассчитывать похожесть заметок и выдавать список связей с оценкой близости.
- Сравнить выбранные локальные модели по скорости, потреблению VRAM и качеству на одинаковом наборе материалов.

**Результат:** модуль, который обогащает заметки, находит материалы по смыслу и отвечает на вопросы с указанием источников.

## Участник 3 — Интерфейс, граф знаний и сквозная проверка

**Зона ответственности:** пользовательские сценарии от загрузки материала до получения ответа.

- Реализовать интерфейс на React + TypeScript.
- Сделать список заметок, карточку материала, редактирование и загрузку файлов.
- Показывать статусы обработки, ошибки, извлечённый текст, краткое содержание и теги.
- Добавить семантический поиск и чат с переходом к заметкам, использованным в ответе.
- Построить граф в Cytoscape.js: узлы — заметки, рёбра — связи, рассчитанные участником 2.
- Добавить выбор узла, просмотр соседних материалов и фильтрацию графа.
- Подготовить сквозные сценарии проверки, демонстрационные материалы и инструкцию пользователя.

**Результат:** интерфейс, через который можно пройти всю цепочку MVP и исследовать связи между заметками.

## Что согласовать втроём до начала разработки

| Договорённость | Что определить |
|---|---|
| Формат заметки | `id`, тип источника, заголовок, исходный и извлечённый текст, вложения, статус, summary, теги |
| Интерфейсы модулей | Форматы запросов и ответов для обработки, поиска, чата и графа |
| Изменение данных | Как обновляются фрагменты, embeddings и связи при редактировании или удалении заметки |
| Критерии готовности | Общий набор материалов и вопросов для проверки MVP |
| Границы локальности | Модели и обработка работают локально; загрузка веб-страниц по ссылкам требует сети |

## Первая интеграция

Первую интеграцию стоит сделать на одной текстовой заметке:

1. Участник 1 сохраняет заметку.
2. Участник 2 формирует summary и индексирует заметку.
3. Участник 3 показывает результат и поиск.

После этого можно параллельно расширять импорт, RAG и граф.

## Тестирование и отчёт

Каждый тестирует свой модуль и описывает его в отчёте. Участник 3 координирует общую проверку, а ошибки исправляет владелец соответствующего компонента.
