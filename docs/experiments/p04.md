# P04: минимальный RAG

Ревью P04 пройдено, обязательных исправлений реализации нет; оценка полноты
исправлена по результатам ревью. До интеграции статус остаётся `review`.
Реальный прогон выполнен 2026-11-13. Реальная цепочка вопрос →
Qwen3-Embedding → SQL pgvector → полные тексты top-3 → Qwen3:8b выполнена
для десяти заранее заданных вопросов. Все ответы опираются на переданный
контекст, три вопроса без ответа получили отказ, частичный вопрос — известный
факт и указание на неизвестную часть. Идеального прохождения нет: два ответа
неполны (r06 и r08), два английских вопроса получили русский ответ.
Интеграция ещё не выполнена.

## Методика и границы

Только `experiments/p04/`, этот отчёт и запись P04 в плане. Backend, корневой
Compose, P01/P02 и существующие изменения P03 не менялись. Переиспользованы
общий runtime `scripts/models/serve.sh`, веса `local/ollama/`, Python-окружение
P02 с Psycopg 3.2.13 и его 24 синтетические RU/EN заметки. Новый runtime,
веса, зависимости, схема или индекс не создавались.

До первого прогона сохранены [вопросы и ожидаемые факты](../../experiments/p04/questions.json),
[конфигурация](../../experiments/p04/config.json) и
[протокол](../../experiments/p04/protocol.json), prepared_utc
`2026-11-13T15:50:47.853197+00:00`. Протокол содержит SHA-256 вопросов,
конфигурации, runner, переиспользованного кода, корпуса, pin моделей и прежних
evidence P01/P02. Вопросы, ожидания и prompt после прогона не менялись.
Ожидания не передаются моделям. Семантическая проверка выполнена агентом вручную
по сохранённым ответам и текстам, это не независимая человеческая приёмка.

Критерии заданы заранее: покрытие ожидаемых фактов, отсутствие добавленных
фактов, явное сообщение о нехватке данных r07–r10. Retrieval проверяется
отдельно от генерации. Score не трактуется как вероятность; порог не
используется и не подбирается по результатам. Близкие заметки без ответа
тоже передаются модели — отказ должен учитывать содержание, а не score.

## Профиль и SQL

- macOS 26.7.2 arm64, Apple M4 Pro 48 GB; Python 3.13.18.
- Общий Ollama 0.40.16, `http://127.0.0.1:11435`, Metal/llamacpp;
  `OLLAMA_CONTEXT_LENGTH=8192`, `OLLAMA_NUM_PARALLEL=1`,
  `OLLAMA_MAX_LOADED_MODELS=1`, `OLLAMA_KEEP_ALIVE=10m` из общего serve.sh.
- Генерация P01: `qwen3:8b`, Q4_K_M, digest
  `500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`.
  `/v1/chat/completions`, temperature=0, seed=42, max_tokens=512,
  reasoning_effort=none, stream=false. Tools и JSON mode не включены.
- Embeddings P02: `qwen3-embedding:0.6b`, Q8_0, digest
  `ac6da0dfba84a81fdbfbaf330198c33cd77c4cdfc53e8bc50eb581914a15621d`.
  1024 измерения, явная L2, `/api/embed`, num_ctx=8192, truncate=false.
  Query instruction и NFC/whitespace normalization переиспользованы из P02:
  `Instruct: Given a web search query, retrieve relevant passages that answer the query`
  и следующая строка `Query: {question}`.
- Изолированный PostgreSQL 17.8 / pgvector 0.8.1 P02,
  `127.0.0.1:55432`, база и роль `p02_experiment`, таблица `p02_notes`.
  Не читаются `.env` и DATABASE_URL. DSN фиксирован в P02.

Runner проверяет digest обеих моделей по evidence/manifest P01/P02 и все
24 ID, языка, заголовка, текста, digest и размерности сохранённых векторов.
Соединение Psycopg — autocommit с серверным
`default_transaction_read_only=on`; выполняются только SELECT. Модельные
вычисления идут вне транзакций. SHA-256 всех строк, включая векторы,
до и после совпал. Переиндексации и DDL нет.

```sql
SELECT id, title, body, 1 - (embedding <=> %s::vector) AS score
FROM p02_notes
ORDER BY embedding <=> %s::vector, id
LIMIT %s;
```

Вектор и limit связаны параметрами Psycopg. Для контекста берутся полный
заголовок и текст каждой из трёх найденных заметок в порядке SQL. ID и score
остаются в экспериментальном evidence и не отправляются генератору.
System prompt требует факты только из заметок, отказ при нехватке данных,
обычный текст на языке вопроса без Markdown, цитат, ссылок и списка источников.
Ответ не размечается и не исправляется постобработкой.

Поддержка ответа контекстом: 10/10, полное покрытие ожидаемых фактов: 8/10,
соответствие языка вопросу: 8/10. Честный отказ на отсутствующий ответ: 3/3;
частичный ответ с оговоркой: 1/1. Все ожидаемые заметки в top-3: 7/7 вопросов,
имеющих ожидаемые заметки, включая r10; у r06 нужны одновременно n10 и n09.
У трёх absent-вопросов проверяется отсутствие факта во всём заранее прочитанном
корпусе, а не совпадение с ожидаемым ID.

Замеченные ошибки и ограничения:

- r06 не назвал короткую транзакцию для проверки/записи и явную проверку lease,
  хотя нужные тексты были переданы. Это неполное покрытие заранее заданных
  ожиданий, а не ошибка retrieval. Фактических противоречий в ответе нет.
- r05 и r08 нарушили требование языка. Межъязыковой retrieval сработал,
  стабильный выбор языка ответа не подтверждён.
- r08 не сообщает известное утро четверга, включённое в заранее заданные ожидания.
  Покрытие ожидаемых фактов не засчитано; честный отказ назвать точный час засчитан.
- r04 содержит грамматическую ошибку «случайный соль».
- r02 воспроизвёл ошибку top-1 P02: n13 выше правильной n21. Генератор выбрал
  нужные факты из top-3. Нижние результаты часто нерелевантны.
- Высокая близость n17/r07 и n12/r08 не означает наличие ответа. Отказ здесь
  прошёл, но гарантии для произвольного корпуса нет.
- Один небольшой синтетический набор, один прогон; нет независимой выборки,
  статистического бенчмарка, проверки длинного контекста, prompt injection,
  истории диалога, конкурентной нагрузки, remote/cloud или интеграции backend.


`PYTHON=/opt/homebrew/bin/python3.13 sh experiments/p02/setup-client.sh` с
фиксированным requirements P02. В этом опыте установка не требовалась.
Если volume P02 отсутствует, сначала воспроизвести P02 по его отчёту с новым
именем evidence; P04 сам не создаёт и не наполняет БД. Новое имя output
обязательно: runner использует exclusive create и отвергает существующий файл.
Для сверки качества нового прогона вручную сравнить ответы с questions.json;
exit 0 runner означает успешное выполнение цепочки, а не оценку смысла ответов.
