# Семестровая работа: локальный LLM-агент для заметок


### Основной функционал

- добавление текстовых заметок, ссылок, изображений/скриншотов и аудиофайлов;
- автоматическое извлечение содержимого: текст из веб-страниц, OCR со скриншотов, транскрибация аудио;
- генерация краткого содержания материала;
- автоматическое присвоение тегов и категорий;
- семантический поиск по базе материалов;
- создание связей между похожими заметками;
- отображение дерева/графа связанных материалов;
- чат с собственной базой знаний в формате RAG;
- полностью локальная работа LLM с использованием GPU.

В качестве модели предполагается протестировать **Qwen 3.x / Qwen Flash-Next / DeepSeek Flash** и выбрать наиболее подходящую по скорости и качеству.

## План работ

1. **Проектирование.** Определить архитектуру приложения, формат хранения заметок и метаданных, выбрать LLM и способ локального инференса.
2. **Базовое хранилище.** Реализовать создание, просмотр, редактирование и удаление заметок; загрузку ссылок, изображений и аудио.
3. **Обработка данных.** Добавить парсинг веб-страниц, OCR для изображений и распознавание речи для аудиофайлов.
4. **Интеграция LLM.** Реализовать суммаризацию, генерацию тегов, определение темы и ключевых сущностей заметки.
5. **Семантический поиск.** Создавать embeddings для материалов и хранить их в векторной БД. Реализовать поиск похожих заметок.
6. **RAG-агент.** Добавить возможность задавать вопросы по накопленным материалам: поиск релевантных записей → передача контекста LLM → генерация ответа со ссылками на исходные заметки.
7. **Связи между заметками.** Автоматически определять связанные материалы и построить визуальный граф/дерево знаний.
8. **Интерфейс и тестирование.** Реализовать UI, провести тесты нескольких локальных моделей на GPU по скорости, потреблению VRAM и качеству ответа.

### Итоговый MVP

Система должна позволять пройти цепочку:

**добавить материал → автоматически обработать → получить summary и теги → найти его семантическим поиском → задать вопрос агенту по всей базе**

## Стек технологий

| Компонент | Технологии |
|---|---|
| Язык | **Python 3.12** |
| Backend | **FastAPI + Pydantic** |
| LLM | **Qwen / DeepSeek**, локальный inference |
| Запуск моделей | **Ollama** для простого MVP или **vLLM** для работы с GPU |
| Embeddings | **sentence-transformers / Qwen Embedding** |
| RAG | **LlamaIndex** или собственная простая реализация |
| Векторное хранилище | **Qdrant** |
| Основная БД | **SQLite** для MVP, при необходимости PostgreSQL |
| Распознавание аудио | **faster-whisper** |
| OCR | **PaddleOCR** или Tesseract |
| Работа с веб-страницами | **BeautifulSoup / trafilatura / Playwright** |
| Frontend | **React + TypeScript** либо **Streamlit** для более быстрого прототипа |
| Граф связей | **Cytoscape.js** |
| GPU | **PyTorch + CUDA** |
| Контейнеризация | **Docker / Docker Compose** |

## Рекомендуемый объём семестровой работы

Для семестрового проекта не стоит пытаться делать полноценный аналог Notion или Obsidian. Достаточно качественно реализовать четыре ключевых направления:

- импорт разных типов данных;
- локальную LLM-обработку;
- RAG-поиск;
- граф связей.

Это даст законченную систему и позволит добавить экспериментальную часть: сравнить несколько моделей по скорости генерации, потреблению VRAM и качеству суммаризации и тегирования.
